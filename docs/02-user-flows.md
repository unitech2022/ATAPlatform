# تدفقات المستخدم (Flows) — من التصميم والمواصفات

## A. الدخول والتسجيل (مشترك)

```
[اللغة] AR / EN
   ↓
[نوع الحساب] راكب (عميل) | سائق
   ↓
[رقم الجوال] +966 + 9 أرقام (يبدأ بـ 5) ← لوحة أرقام مخصصة
   ↓  POST /auth/otp/request
[رمز التحقق] 4 أرقام، إعادة إرسال بعد 60 ث، صلاحية 5 د، 5 محاولات
   ↓  POST /auth/otp/verify
راكب ──→ [الاسم + الموافقة على الشروط] (أول مرة فقط) ──→ التطبيق
سائق ──→ [تم إنشاء طلبك] رقم الطلب ATA-XXXXX، الخطوات: (1) رفع المستندات عبر الموقع (2) مراجعة الإدارة 24–48 س (3) تفعيل الحساب
            ├─ زر "الانتقال لموقع رفع المستندات" (رابط الموقع + رمز دخول)
            └─ بعد التفعيل: بوابة السائق
```

قواعد:
- لا بريد إلكتروني. المفتاح الداخلي `user_id` (UUID)، ورقم الجوال فريد وموثق.
- OTP: تحديد معدل 3 طلبات / 10 دقائق لكل رقم، و10 / ساعة لكل IP. قفل مؤقت بعد 5 محاولات خاطئة.
- في بيئة التطوير يُعاد الرمز في الاستجابة (`devCode`) ولا تُرسل SMS.
- الحساب الذي يملك دور "سائق" و"راكب" معاً مسموح (نفس الرقم)؛ يُحدد الدور النشط عند الدخول.

## B. تطبيق الراكب

**الرئيسية (خريطة + لوحة الطلب)**
1. موقع الانطلاق (الموقع الحالي، قابل للتعديل).
2. محطات إضافية (حتى حد الفئة، مثلاً 2).
3. الوجهة (بحث).
4. الوقت: الآن | جدولة (تاريخ/وقت، حد أقصى 7 أيام).
5. خيار "أفضّل سائقة" (للعميلات، عند توفرها).
6. اختيار الفئة: توفير، اقتصادي، مريح، عائلي (XL)، ATA بلس (Premium)، المطار — مع ETA والسعر التقديري.
7. طريقة الدفع: نقداً | محفظة ATA | بطاقة (مدى/Visa/MC/Apple Pay).
8. زر "اطلب {الفئة} · {السعر}".
9. حالة "جاري البحث عن كابتن" + إلغاء الطلب.
10. (الخطوة 2) السائق المعيّن: الصورة، الاسم، التقييم، السيارة، اللوحة، ETA، تتبع مباشر، PIN.

**الهيدر**: جرس الإشعارات (عدّاد)، الشعار، المحفظة، قائمة (الملف الشخصي، إعدادات الحساب، اللغة، الإشعارات، السلامة والخصوصية، اتصل بنا).

**رحلاتي**: قائمة الرحلات (المكان، التاريخ، السعر، الحالة: مكتملة/ملغاة/جارية) + بطاقة "احجز رحلة الآن".

**المحفظة**: بطاقة الرصيد الداكنة، طرق الدفع (محفظة ATA — مدى — نقداً)، شحن المحفظة (50/100/200 أو مبلغ مخصص) → شاشة نجاح.

**السلامة**: مشاركة الرحلة، مركز المساعدة، جهات موثوقة، "هل تحتاج مساعدة عاجلة؟" (طوارئ).

**حسابي**: بطاقة الملف (الاسم، عضو منذ، التقييم)، الإعدادات: البيانات الشخصية، الأماكن المحفوظة، الخصوصية والأمان، الإشعارات (تفضيلات: الرحلات/المحفظة/السلامة/العروض)، اللغة، اتصل بنا، الشروط والأحكام، تسجيل الخروج، حذف الحساب (تأكيد).

## C. تطبيق/بوابة السائق

**الحالة قبل التفعيل**: شاشة "طلبك قيد المراجعة" مع حالة كل مستند (مطلوب / قيد المراجعة / مقبول / مرفوض + السبب) وزر رفع المستندات (داخل التطبيق أو عبر الموقع).

**بعد التفعيل — نظرة عامة**: مفتاح متاح/غير متصل، بطاقات: أرباح اليوم، الرحلات، ساعات العمل، التقييم؛ آخر الرحلات؛ بطاقة أرباح الأسبوع مع هدف الأسبوع + زر تحويل الأرباح.

**المستندات والمركبة**: الهوية الوطنية/الإقامة، رخصة القيادة، استمارة المركبة، التأمين، صورة شخصية — مع تاريخ الانتهاء والحالة؛ بطاقة المركبة (الماركة، الموديل، اللون، السنة، اللوحة) + تحديث.

**إعدادات الحساب**: البيانات الشخصية، الحساب البنكي (IBAN)، إعدادات الرحلات (نطاق العمل، التفضيلات)، الإشعارات، اللغة، المساعدة والدعم، تسجيل الخروج.

**(الخطوة 2) استقبال الرحلة**: الالتقاط، الوجهة، المسافة، ETA، سعر الراكب، صافي أرباح السائق، قبول/رفض بمهلة → التنقل → Arrived → Waiting → PIN → In Trip → Complete.

## D. الموقع (website)

1. صفحة تعريفية (Hero بالشعار والألوان، الفئات، السلامة، انضم كسائق، روابط المتاجر).
2. **بوابة السائق لرفع المستندات**: دخول برقم الجوال + OTP (نفس الحساب) → حالة الطلب → نموذج البيانات الشخصية → بيانات المركبة → رفع كل مستند (PDF/JPG/PNG حتى 10MB) مع تاريخ الانتهاء → إرسال الطلب للمراجعة → متابعة الحالة.

## E. لوحة الإدارة (dashboard)

1. تسجيل دخول مؤسسي (اسم مستخدم + كلمة مرور، MFA لاحقاً).
2. لوحة رئيسية: أرقام موجزة (طلبات السائقين المعلقة، السائقين النشطين، الركاب، الرحلات اليوم).
3. **طلبات السائقين**: قائمة بفلتر الحالة → تفاصيل الطلب (البيانات، المركبة، المستندات مع معاينة) → قبول/رفض مستند مع ملاحظة → اعتماد/رفض/تعليق الحساب. كل إجراء يُسجَّل في Audit Log.
4. الركاب: قائمة وبحث وتعليق.
5. فئات الرحلات: إدارة (الاسم بالعربية/الإنجليزية، الوصف، عدد المقاعد، الحد الأقصى للمحطات، الترتيب، مفعّلة).
6. (لاحقاً) الرحلات، التسعير، المناطق، الطلب، العروض، الحوافز، المدفوعات، المحافظ، الشركات، الدعم، السلامة، التقارير، الصلاحيات.

## F. دورة حياة الرحلة (مرجع للخطوة 2)

`Requested → Searching → DriverAssigned → DriverEnRoute → DriverArrived → Waiting → PinVerified → InTrip → Completed | Cancelled`

كل انتقال يُسجل في `trip_events` مع الطرف والوقت والموقع، وكل إلغاء يُسجل `cancellation_event` بالمرحلة والسبب والطرف.
